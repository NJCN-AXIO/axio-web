## 1. 目标

官网公开预览必须忠实复刻当前 AXIO 产品，而不是重新设计一套概念界面。桌面端的布局、导航、视觉样式、字段、状态、弹窗和主要交互以产品提交 `eef0f87` 中已跟踪的前端文件为唯一来源。

预览部署为 GitHub Pages 可托管的纯静态站点，不连接产品服务器，不读取真实运行数据，也不执行真实采集、上架、改价、优化或配置写入。

## 2. 官网入口

- 原网站主操作“预约产品演示”改为“在线体验”。
- 桌面主导航右侧、首页主操作和移动导航中的同一主操作均指向 `/preview/`。
- “在线体验”保持现有主按钮的醒目层级，不新增第二个竞争入口。
- 现有官网页面、排版和视觉不做无关改动。
- `/demo/` 继续保留，作为联系、预约和视频材料页面；它不再承担主要产品体验入口。

“在线体验”准确表达可操作的网页体验，同时避免暗示预览已连接真实店铺或生产后端。

## 3. 默认状态

- 打开 `/preview/` 后默认进入产品的“新建任务”页面。
- 左侧导航和页面标题必须同步显示该激活状态。
- 刷新页面后恢复到已定义的脱敏初始状态，不沿用产品仓库或用户设备中的真实状态。
- 页面提供返回 AXIO 官网的明确入口，但不得改变产品主体的桌面布局。

## 6. 本地模拟架构

预览由四层组成：

### 6.1 产品视图层

保留产品 HTML、CSS 和主要 DOM 交互。除资源路径、品牌、默认页、移动端适配和模拟接口接入外，不重新设计。

### 6.2 本地传输层

产品代码中的请求统一调用 `demoRequest()`。该函数只查询浏览器内的路由表，不调用 `fetch`、XHR、WebSocket、EventSource 或外部脚本。

返回对象保持产品代码所需的 `ok`、`status`、`json()`、`text()` 和 `blob()` 语义，使原有页面逻辑能够继续工作。

### 6.3 脱敏数据层

固定 fixtures 提供虚构的店铺、站点、商品、关键词、订单、任务、定价、风险、AI 主管和优化结果。数据必须满足：

- 不使用真实店铺名、账号、订单号、商品 ID、手机号、邮箱、价格台账或内部任务标识；
- 不复制产品仓库的数据库、配置和运行 JSON；
- 数值在各页面之间保持一致，能支持完整交互；
- 明确显示“演示数据”或“本地模拟”，避免被理解为真实经营数据。

### 6.4 会话状态层

本地模拟写操作更新内存状态，并可在当前标签页会话中保持。刷新页面恢复初始 fixtures。预览不写 Cookie，不上传文件，不向官网表单提交业务数据。

## 7. 代表性交互

- **新建任务：** 修改来源、关键词、站点、店铺和策略，生成预检，确认后展示分阶段进度和完成回读。
- **任务历史：** 查看新建的模拟任务、筛选状态、展开详情并模拟重试。
- **店铺管理：** 搜索、分组筛选、查看容量和切换发布选择。
- **选品链路：** 从热销采集进入候选数据，导入关键词，查看评分与策略分层。
- **矩阵运营：** 保留当前经营看板和作战计划标签、筛选和汇总交互。
- **智能优化：** 选择优化类型，生成预览，确认模拟任务并显示结果。
- **标题学习：** 查看候选、筛选、评分和模拟审核。
- **违禁管控：** 添加、编辑、删除本地规则并运行模拟扫描。
- **系统配置：** 切换演示配置、测试本地状态并显示成功反馈；不展示或接收真实密钥。
- **AI 主管：** 切换权限模式、提交示例问题并返回固定的脱敏分析或计划。

## 8. 响应式行为

- 桌面端保持产品现有侧边栏和内容区域布局。
- 小屏设备把侧边栏变为可关闭抽屉，保留所有导航项。
- 原产品控件的文字、表格和弹窗不得横向溢出或互相遮挡。
- 交互控件最小触控高度为 44px。
- 移动适配不得改变桌面端的视觉基准。

## 9. 安全边界

公开预览必须满足：

- 构建产物中没有真实凭证、Cookie、令牌、手机号、邮箱、店铺名、生产 ID 或供应商私有地址；
- 没有真实网络请求能力；
- 没有后端、数据库、文件系统或平台自动化依赖；
- 文件上传只读取文件名和浏览器临时对象，不上传内容；
- 所有高风险按钮只改变本地模拟状态；
- GitHub Pages 根路径和仓库子路径 `/axio-web/` 均可运行。

安全扫描以“无真实网络 primitive、无外部 URL、无敏感字段和值、无运行数据文件”为门禁。产品原有的本地请求键可以作为模拟路由标识存在，但不能绕过 `demoRequest()`。

## 10. 测试策略

实现遵循测试驱动开发：

1. 先写失败测试，固定官网“在线体验”入口和默认新建任务页。
2. 先写失败测试，固定产品全部导航项和关键 DOM 结构。
3. 先写失败测试，证明任何产品操作不会产生网络请求。
4. 按页面增加代表性交互测试并观察失败，再实现对应 fixture 和状态转换。
5. 增加敏感数据、外部地址和不允许文件类型的构建扫描。
6. 桌面和移动端运行完整 E2E。
7. 分别验证根路径和 `/axio-web/` GitHub Pages 子路径。

## 11. 验收标准

- 官网主操作显示“在线体验”并进入 `/preview/`。

- 安全扫描确认没有真实数据和敏感文件。
- 官网既有页面无视觉或功能回归。
- 根路径与 `/axio-web/` 静态导出均通过测试。
