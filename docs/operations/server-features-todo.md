# 有服务器后继续的待办清单

更新日期：2026-07-20

## 当前发布边界

`master` 只发布 GitHub Pages 静态官网。当前不提供账号注册、邮箱验证、登录、会员中心、授权下载、数据库写入、本地客户端启动接口或在线支付。

演示预约仅在配置 `NEXT_PUBLIC_DEMO_FORM_ENDPOINT` 后由浏览器提交到 Formspree；未配置时不会提交个人信息，并保留微信二维码联系入口。

当前静态架构见 `../architecture.md`，发布方式见 `github-pages-deployment.md`。

## 恢复前必须先做的决定

- [ ] 确认是否真的需要公开注册，还是只需要邀请制账号。
- [ ] 选择运行平台：Supabase、Cloudflare、托管 Node.js 或 VPS。
- [ ] 决定继续 Prisma/Auth.js，还是迁移到平台原生认证和数据访问。
- [ ] 定义会员中心首发范围：许可证、下载、启动码、支持请求分别是否必要。
- [ ] 明确数据保留、隐私政策、删除请求和管理员访问流程。

该决策应形成单独 ADR。不要在平台未确定前直接把整个 `future/server-features` 合并回 `master`。

## 基础设施前置条件

- 可持续运行的服务器或兼容 Next.js 的托管运行时
- 正式 PostgreSQL 和隔离的测试数据库，或经 ADR 批准的替代数据库
- SMTP 发信账户与已验证发件域名
- HTTPS 正式域名、准确的应用基础 URL 和高强度 `AUTH_SECRET`
- S3 兼容对象存储或托管存储，用于安装包和固定下载地址
- 平台级密钥管理，严禁把密钥提交到仓库
- 日志、监控、备份和恢复目标

## 分支恢复方式

检查服务端基线：

```powershell
git switch future/server-features
git switch -c deploy/server-runtime
```

继续 Task 9 测试检查点：

```powershell
git switch wip/member-center
npm test -- src/server/member "src/app/(member)"
```

`wip/member-center` 当前预期为 RED，因为只提交了授权策略、账户布局和下载页测试，生产实现尚未创建。

恢复前先保存当前工作区并确认目标分支，不要在静态 `master` 上直接运行数据库迁移。

## 上线门槛

以下条件全部满足后，服务端功能才能对外：

- 注册、验证、登录、授权和下载的正向与反向测试通过。
- 生产数据库有自动备份并完成一次恢复演练。
- 密钥不出现在 Git、浏览器包、日志或错误页面。
- 邮件域名验证、退信处理和发送限额已确认。
- 所有状态变更 API 有鉴权、校验、速率限制和审计日志。
- 隐私政策准确描述收集字段、用途、保留和删除方式。
- 静态官网仍可独立发布，服务端故障不会破坏公开内容页。
