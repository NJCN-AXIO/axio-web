# 免费托管方案建议

更新日期：2026-07-20

免费额度和产品限制会变化。本文记录架构选择，不把具体额度当作长期承诺；启用前应重新核对服务商官方页面。

## 当前推荐：GitHub Pages + Formspree + 微信

当前 `master` 已按这套组合实现：

| 能力           | 服务         | 费用倾向     | 当前用途               |
| -------------- | ------------ | ------------ | ---------------------- |
| 静态网页和 CDN | GitHub Pages | 免费         | 发布 Next.js `out/`    |
| 演示预约       | Formspree    | 有免费层     | 浏览器直接提交表单     |
| 直接联系       | 微信二维码   | 无服务器费用 | 表单未配置时的稳定兜底 |

优点：

- 不购买服务器也能发布官网。
- 没有数据库、系统补丁和常驻进程维护。
- GitHub Actions 自动验证和部署。
- 网站故障面较小，回滚只需 Git revert。

限制：

- 不能运行注册、登录、会员中心和许可证 API。
- 不能在 AXIO 自有数据库保存预约。
- Formspree 的免费提交量、通知、保留时间和反滥用策略受其套餐约束。
- 大视频仍会消耗仓库和 Pages 带宽，应控制数量与体积。

Formspree 官方限制说明：
https://help.formspree.io/articles/account-management/account-limits

## 什么时候需要后端

出现以下需求之一时，应从纯静态架构升级：

- 用户注册、邮箱验证和登录
- 会员中心、许可证、授权下载
- 演示预约进入自有数据库
- 管理后台、状态跟踪和销售分配
- 一次性客户端启动码
- 自有邮件通知、审计日志或复杂反滥用规则

升级不等于必须购买传统 VPS。可以先选择托管数据库、认证或边缘函数，但必须接受代码适配成本。

## 方案 A：Supabase

适合希望快速获得 PostgreSQL、认证、存储和管理界面的阶段。

优点：

- 数据库、认证和对象存储组合完整。
- 免费层适合低流量验证。
- 减少自建数据库和认证基础设施。

代价：

- 现有 Prisma/Auth.js 服务端基线不能保证原样运行。
- 需要重新评估认证流程、Row Level Security、邮件模板和迁移策略。
- 免费项目的休眠、配额和备份策略必须上线前复核。

官方定价：
https://supabase.com/pricing

## 方案 B：Cloudflare Pages、Workers 和 D1

适合低流量 API、边缘表单处理和简单数据服务。

优点：

- 静态资源与边缘函数组合紧密。
- 全球分发，低流量阶段成本低。
- D1、R2 可覆盖部分数据库和对象存储需求。

代价：

- Workers 不是完整 Node.js 常驻服务器。
- Prisma、Auth.js、SMTP 和部分 Node.js 依赖需要适配。
- CPU 时间、请求、数据库一致性和本地开发方式与传统服务器不同。

官方限制：
https://developers.cloudflare.com/workers/platform/limits/

## 方案 C：托管 Node.js 平台

如果目标是尽量保留 `future/server-features` 中的 Prisma/Auth.js 代码，应选择支持 Next.js 服务器运行时和外部 PostgreSQL 的平台。

可评估 Render、Railway、Fly.io 或其他托管平台。选择前逐项确认：

- 免费实例是否休眠及唤醒时间
- 是否允许出站 SMTP
- PostgreSQL 是否独立计费、是否自动备份
- 构建时长、内存、流量和文件系统限制
- 自定义域名和 HTTPS
- 环境变量、日志、回滚和区域

这些平台的免费政策变化较频繁，仓库不记录具体免费额度。

## 方案 D：VPS

VPS 的代码兼容性最高，但不是“免费且免维护”的方案。需要自行负责：

- Linux 更新、防火墙、SSH 和最小权限
- Node.js 进程、反向代理和 TLS
- PostgreSQL 或外部数据库
- 备份、监控、日志轮转和故障恢复
- SMTP、对象存储和密钥轮换

在账号和会员功能尚未产生稳定价值前，不建议仅为了“以后可能用到”提前购买 VPS。

## 推荐推进顺序

1. 当前阶段：GitHub Pages + 微信，必要时启用 Formspree。
2. 有稳定预约量后：评估是否需要自有数据库和销售状态管理。
3. 确认账号/授权需求后：在 Supabase、Cloudflare 或托管 Node.js 之间做一次架构决策。
4. 只有在需要最大兼容性、固定资源或私有化控制时再考虑 VPS。

服务端恢复任务见 `server-features-todo.md`。
